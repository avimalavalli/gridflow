# GridFlow Milestone 6 — Outreach Operations

Validated on 20 July 2026.

## Objective

Milestone 6 turns the approved outreach generated by Echo into a controlled operating workflow. It adds a real LinkedIn action queue, Gmail account infrastructure, policy-controlled email delivery, mailbox reply synchronisation and automatic sequence stopping.

GridFlow remains organisation-based and multi-athlete. Every integration account, message, action, suppression entry and interaction is tenant-scoped.

## Built in this milestone

### Gmail connection and credential safety

- Server-side Google OAuth web flow with signed, expiring state.
- Organisation membership is rechecked during the OAuth callback.
- Access and refresh tokens are encrypted with AES-256-GCM before database storage.
- Automatic access-token refresh.
- Connect, status, manual sync and disconnect endpoints.
- Settings interface showing connection and sync status without exposing credentials.

### Policy-controlled email operations

The Outreach Workbench now supports:

- Create Gmail draft.
- Send an approved email immediately.
- Queue email according to the athlete's policy.
- Select initial email, follow-up 1 or follow-up 2.
- Suppress a recipient and pause the sequence.

Before any queued email is executed, the worker rechecks:

- message approval;
- email automation mode;
- approval mode;
- sending day and time window;
- daily email cap;
- reply state;
- meeting state;
- suppression state;
- active conversation with another contact at the same company;
- high-value approval threshold.

Manual, Draft Only, Approved Automatic and Full Automation modes are all supported. A queued action is never treated as permanent permission: policy is evaluated again when the worker actually handles it.

### Duplicate-send and failure protection

- Stable idempotency keys are shared with the existing agent engine.
- Legacy and new sequence-step names are normalised before execution.
- Sent, replied, bounced and suppressed actions cannot be silently requeued.
- Interrupted email jobs are recovered.
- Failed actions retain error details for the operations queue.
- Draft creation is recorded separately from actual sending.

### Reply and bounce synchronisation

- Gmail History API cursor is stored per organisation.
- Expired history cursors fall back to a bounded recent-mail sync.
- Incoming messages are matched by Gmail thread first and sender email second.
- Replies create inbound interactions, update contact status and pause pending email actions.
- Bounces update outreach state and create suppression entries.
- Duplicate Gmail messages and duplicate bounce suppression entries are ignored.
- The worker checks connected inboxes periodically; an operator can also trigger a manual sync.

### LinkedIn operating queue

LinkedIn remains human-controlled. GridFlow now records and schedules:

- connection sent;
- connection accepted;
- follow-up due;
- follow-up sent;
- reply received;
- no response;
- paused;
- not interested.

Each action updates the outreach state, creates or updates a durable ChannelAction, records the interaction direction correctly and pauses pending actions when the conversation changes state.

### Outreach Operations screen

The Outreach screen now exposes:

- approvals waiting;
- LinkedIn actions due;
- queued emails;
- replies;
- failed actions;
- suppressed sequences;
- a prioritised cross-channel action queue.

## Required environment variables for live Gmail use

```bash
GOOGLE_OAUTH_CLIENT_ID=
GOOGLE_OAUTH_CLIENT_SECRET=
GOOGLE_OAUTH_REDIRECT_URI=
INTEGRATION_ENCRYPTION_KEY=
GOOGLE_OAUTH_STATE_SECRET=
```

`GOOGLE_OAUTH_STATE_SECRET` may be omitted when the encryption key should also sign OAuth state.

## What was not claimed

No real Gmail account was connected in this development environment. No live email was sent. The OAuth, API client, policy engine, database operations, queue handling and UI were validated through automated and disposable-database tests, but final Google Cloud configuration and live mailbox acceptance testing remain release-owner tasks.

No LinkedIn sending automation was added. GridFlow controls the workflow around LinkedIn, while the user performs the platform action.
